## 0. 目的

[candle_pattern_backtest.md](candle_pattern_backtest.md) は 14 パターンすべてを否決したが、その結論は
**562 銘柄をプールした平均**の上に立っている。したがって「小型株のノイズで希釈されているだけで、
大型株に絞れば形状に予測力があるのではないか」は、結論に対する正当な反証仮説として残っている。

**この検証の出口は、その反証仮説を潰して既存 docs の主張を強くすることである。**

**スクリーニングへのフィルタ追加を出口にしない。** in-sample で有意に出た行をそのまま製品に載せることは、
`TREND_BONUS = 0`（[backtest_gotchas.md](backtest_gotchas.md)「検証結果として確定していること」）や
「スクリーニング UI にスコアを出さない」で積み上げてきた判断 — **前方リターンを見て設計を選ばない** — と
正面から矛盾する。

## 1. 母集団の設計

### 1.1 ランダム対照群も同じ 159 銘柄に絞る

2021〜2026 の日本株は大型株優位の期間だった。シグナル側だけを大型株に絞り、ランダム側を
562 銘柄のままにすると、差の列に大型株プレミアムがそのまま乗り、**「パターンが効いた」ではなく
「大型株が上がった」を測る**ことになる。

「仮説に有利な条件で測り、それでも否決なら強い」という論法は片側にしか通らない。
**有意が出てしまった場合に形状の寄与と大型株プレミアムを分離できない。**
それは §4 で一度払った授業料（「形状 かつ 文脈」の合成数字から寄与を分離できなかった）そのものである。

`candle_backtest.main` は同じ `codes` を `collect_signals` と `random_returns` の両方に渡しているので、
**`codes` を絞れば両側に効く**。この配線を壊さないこと。

### 1.2 規模の指標は時価総額ではなく売買代金

**時価総額は使えない。** 理由は 2 つある。

1. **データが無い。** `topix_universe.csv` は `code,name` の 2 列しかない。`market_cap` を持つのは
   `prime_universe.csv`（225 銘柄）だが、**それは CSV 作成時点のスナップショット 1 点**である
2. **point-in-time で計算できない。** `ohlcv_store` は `auto_adjust=True` で保存しており、
   `screening_provider._last_bar` のコメントが明言するとおり**過去バーは実際の株価ではない**。
   実行時の解決経路（`_resolve_asof_cap` = 発行済株式数系列 × 終値）はバックテストに繋がっていない

スナップショットで全期間を絞ると look-ahead になる。調整後終値の比で遡及推定した実測値:

| 事実 | 値 |
|---|---|
| 1兆円超 159 銘柄のうち推定できたもの | 156 |
| **2021-08 時点では 1兆円未満だった推定** | **55 銘柄（35%）** |
| 最大の膨張 | フジクラ 0.35兆 → 13.94兆（**39.8 倍**） |
| 以下 | 三菱重工 14.1 倍 / 古河電工 13.1 倍 / アドバンテスト 11.1 倍 / IHI 8.7 倍 |

**母集団の 3 分の 1 が「この 5 年の勝ち組」で構成される。** §1.1 で両側を同一母集団にするので
大半は相殺されるが、**完全には消えない** — ハンマーのような文脈条件付きシグナルは下落局面で
発火するため、「結局上がると分かっている銘柄の押し目」だけを見ることになる。ランダム側は
無条件の日を引くので、この非対称は相殺されない。★ が付いていたのがまさにハンマーである以上、無視できない。

**そこで `Close × Volume`（売買代金）を使う。** 根拠は 3 つ。

- **分割に対して不変**（分割で価格 1/n・出来高 n 倍）。調整済みストアのままで正しく計算できる唯一の規模指標
- **追加取得がゼロ。** ストア内のデータだけで point-in-time にローリング計算できる
- 「大型株なら違うのでは」という仮説の実質的な中身は**流動性と参加者構成**であって、発行済株式数ではない

**この置き換えは「時価総額 1兆円」という問いの言い換えである**ことを自覚しておく。換算点の実測:

| 売買代金の閾値 | 銘柄数 | 時価総額 1兆超 159 銘柄の捕捉率 |
|---|---|---|
| 10 億円/日 | 409 | 100% |
| 30 億円/日 | 214 | 94% |
| **50 億円/日** | **155** | **81%** |

件数が 159 とほぼ一致するのは 50 億円/日。なお 1兆円超 159 銘柄の売買代金は
**min 20.2億 / 中央 89.4億 / max 1666億** と 80 倍の開きがあり、**時価総額と売買代金は 1 対 1 ではない**。

### 1.3 切り方は各時点の売買代金上位 159 銘柄

絶対額固定は取れない。2021 年と 2026 年では市場全体の売買代金水準が違うので、同じ「50 億円/日」でも
**前期と後期で母集団のサイズが変わり**、§3.1 と §3.2 を並べたときに期間差なのか母集団差なのかを分離できない。

件数を固定する。159 という数字は元の 1兆円仮説の粒度をそのまま引き継ぐので、
§1.2 の指標差し替えによる**質問の置き換え幅が最小**になる。

判定式は次のとおり。

```
turnover = Close * Volume
roll     = turnover.rolling(60, min_periods=40).median().shift(1)   # shift(1) で当日を見ない
mask     = roll.rank(axis=1, ascending=False, method="first") <= 159
```

**`shift(1)` を落とさないこと。** 当日の売買代金でその日の母集団を決めると、
「その日たまたま出来高が膨らんだ銘柄」を後知恵で選ぶことになる。

**閾値は 1 本だけ事前に確定し、複数試して良かった線を採らない。**
50億/100億/上位100/上位200 を並べて一番よく ★ が出た線を採るのは多重検定の産物であり、
`PPP_GAP_K` を「効果で選んでいない・物理的意味で先験的に置いた」と決めた判断
（[ppp_screening_spec.md](ppp_screening_spec.md) §5.1）と矛盾する。

### 1.4 リバランスは各 run の期首で 1 回だけ

入れ替わりの実測:

| 事実 | 値 |
|---|---|
| 後期 3 年間での構成入替 | 159 中 **35 銘柄**（期首と期末で 124 が共通） |
| 前期期首 → 後期期末（4.5 年） | 入替 42 |
| 全期間ずっと上位 159 にいた銘柄 | 89 |

**日次リバランスと期首固定の母集団は 78% 一致する。** 日次リバランスが買えるのは残り 22% の
忠実さだけで、その対価として `random_returns` のシグネチャを日次母集団対応に変える必要がある。
あの関数は **旧 §7（現 §8）で「シグナル側 562 / ランダム側 565 の母集団不一致」という未修正の欠陥が
すでに文書化されている**まさにその場所であり、そこへ日次の母集団管理を持ち込むのは、
同じ種類のバグを 1225 倍の面で再導入する賭けになる。

「期首固定だったから結論が違うのでは」という反論には**「母集団は 78% 同一」と数字で答える**。

### 1.5 前期先頭 40 営業日は 2021-09-24 のランキングを遡及適用する

60本中央値は最低 40 本を要求し、ストア先頭が 2021-07-27 なので、**ランキングが確定するのは
2021-09-24 から**。前期の開始 2021-08-01 では母集団を決められない（40 営業日 ≒ 前期の 9%）。

§3.2 と**期間を完全一致させることを最優先**する。Q2 で対照群を揃えたのと同じ論理で、
交絡は一度に 1 つずつしか潰せない。「大型株だから違う」を検証したいときに期間までずらすと、
差が出たときにどちらのせいか言えなくなる。

遡及による look-ahead の大きさは実測済み:

| 比較 | 母集団の乖離 |
|---|---|
| 2021-09-24 判定 vs 1 ヶ月後 | 8 銘柄 |
| 同 vs 2 ヶ月後 | 11 銘柄（**約 6%**） |
| 同 vs 1 年後 | 18 銘柄 |

**前期だけ判定窓を 3 本に縮める案（2021-08-01 で判定でき、look-ahead ゼロ）は採らない。**
前期と後期で判定規則が非対称になる。`candle_patterns.py` に `shooting_star` だけ文脈を見ないという
非対称が残り、今も注記を書き続ける負債になっていることを考えると、同種のものを自分から増やす価値はない。

### 1.6 品質フィルタはランキングの前に適用する

562 銘柄からランク上位 159 を取る（565 から取ってから落とすのではない）。
8303 は負値を含むため `Close × Volume` の順位自体が無意味であり、
フィルタを後に掛けると母集団が 158 に欠ける。

## 2. 統計の扱い

### 2.1 旧 §7（現 §8）を先に直す（既存 §3.1 / §3.2 も測り直す）

`collect_signals` はシグナル側に品質フィルタを掛けるが `random_returns` には無い、という
[candle_pattern_backtest.md 旧 §7（現 §8）](candle_pattern_backtest.md) の既知欠陥を、**この検証の前に直す。**

品質不良は `8227` / `8303` / `6632` の 3 銘柄。**うち 8303 が前期の 159 銘柄に入っている。**

| 8303 の状態 | 値 |
|---|---|
| 負値を含む行 | 245 / 693 |
| 最大日次リターン | **+1,977万%** |

ランダム母集団が 565 → 159 に縮むと、8303 が引かれる確率は **1/565 → 1/159 で 3.5 倍**になる。
旧 §7 が「seed 1 で差が -445298% になった」と記録した状態を、当たり確率 3.5 倍で再演することになる。

**事後確認では足りない。** 旧 §7 は「seed 0 で壊れていない根拠は、差の列が全 56 行で ±1.5% に
収まっていることの 1 点に尽きる」と書いている。それは**壊れたときに気づく**手段であって、
壊れないことの保証ではない。

**既存 §3.1 / §3.2 も測り直す。** この検証の成果物は「562 銘柄では否決 / 大型株 159 銘柄でも同様」と
**2 つの表を並べること自体**である。ランダム母集団の作り方が違う 2 表を並べると、
§1.3 が禁じている「表をまたいだセル比較」を、よりによって結論の中核でやることになる。

### 2.2 帯による二値判定をせず、CI 上限を報告する

n は 28〜35% に落ちるので CI は広がる。**CI が 0 を跨いだだけでは「否決」を意味しない** —
「効果が無い」のか「n が足りなくて見えない」のかが区別できず、後者なら「大型株でも否決」は事実に反する。

等価性検定（無視できる帯に CI 全体が収まったら効果なしと言う）も採らない。**帯を選べないため。**

- 経済的に「無視できる」と言える帯は **±0.2% 程度**（大型株の往復実効コスト）
- 統計的に解像できるのは **±1.0% 程度**

この 2 つが一桁近く離れている。fwd10 で 0.5% は年率 12%、1.0% は年率 25% 相当であり、
**「年率 25% 相当を無視できると呼ぶ」のは語義矛盾**になる。かといって帯を通過率で選ぶのは、
`PPP_GAP_K` を効果で選ばなかった判断と矛盾する（既存 88 行の CI 幅を 1.77 倍したとき、
±0.5% に収まるのは 9 行、±1.0% なら 49 行 — この表を見て帯を決めた時点で in-sample への当てはめになる）。

**したがって「効果があるとしても fwd10 で X% 以下」という上限を報告する。**
帯を選ぶ問題そのものが消え、かつ目的にも合う。欲しいのは「否決」という札ではなく
**「大型株に絞っても、形状で説明できる余地はこの幅までしかない」という上限**である。

**結論の文型が既存 §5（「14 パターンすべて否決」）とは変わる**ことを受け入れる。

なお救いが 1 つある。ブートストラップの再抽出単位は**日付**であって銘柄ではなく、
同時線が事実上全営業日に出るので**日付数はほとんど減らない**。減るのは 1 日あたりのシグナル数だけなので、
CI の広がりは `1/√0.32 = 1.77 倍` より小さくなるはずだが、どこまで小さいかは実測しないと分からない。

### 2.3 §4 の分解を大型株でも同時に測る

**大型株フィルタを足すと、ハンマーは条件が 3 つになる** — 形状 かつ 下降文脈 かつ 大型株。
[CLAUDE.md](../../CLAUDE.md) の「条件を 2 つ以上持つ検出器を足したら、条件ごとに分けて測ること」は
まさにこの状況のための行である。ランダム比だけの表を作れば、大型株ハンマーに ★ が付いたとき
「大型株では形状が効く」と読める行が生まれるが、**3 条件の合成数字からはどの条件の寄与かを分離できない。**

測る系列は**結果を見る前に確定する**（CI 上限が大きく出た行だけ後から分解するのは事後選択）。

後期の系列別 n（全 562 → 大型株 159）:

| 系列 | 全体 | 大型株 159 |
|---|---|---|
| 形状のみ | 32,021 | 9,020 |
| 下降文脈のみ | 55,909 | 18,076 |
| 上昇文脈のみ | 89,856 | 26,595 |
| ハンマー（形状 かつ 文脈） | 4,146 | 1,333 |
| 首吊り線（形状 かつ 文脈） | 6,723 | 1,947 |

**§4 のスクリプト化が前提になる。** §8 が「§4 と §6 の測定はスクリプト化していない」と明記するとおり
あの 5 系列は手作業で回されたもので、§2.1 で数値が動く以上、再現できないと §4 の表が孤児になる。

### 2.4 ★ は残すが多重検定補正を掛けない

表は 56 行 → 112 行 + §4 の系列に増え、α=0.05 の偽陽性期待値は 2.8 → 5.6 以上になる。

**Bonferroni は前提が崩れている。** 56 行は独立ではなく、**同じ日付・同じ銘柄・重なるバーを共有している**
（同時線は全営業日に出るので、他のすべてのパターンと日付集合が重なる）。独立を仮定した補正は
保守的というより**どれだけ保守的か分からない**数字になる。

既存の流儀 — 「偽陽性期待値と実測数を突き合わせ、有意行を 1 行ずつ潰す」 — を継続する。
**★ は判定ではなく、追検証すべき行の目印である**と表の凡例に明記する。

## 5. やってはいけないこと

- **シグナル側だけを大型株に絞らない**（§1.1）
- **時価総額のスナップショットで全期間を絞らない**（§1.2 / 母集団の 35% が look-ahead）
- **売買代金の判定に当日を含めない**（§1.3 / `shift(1)` を落とさない）
- **閾値を複数試して良かった線を採らない**（§1.3）
- **等価性の帯を通過率で決めない**（§2.2）
- **旧 §7 を直さずに走らせない**（§2.1 / 8303 の当たり確率が 3.5 倍）
- **測る系列を結果を見てから決めない**（§2.3）
- **前期・後期をまとめて n を稼がない。** §3.5 や §4 のとおり**符号が期間で反転する**ので、
  まとめると反転が平均で打ち消されて「効果ゼロ」に見える。今回いちばん犯してはいけない誤り
- **有意な行が出てもスクリーニングに載せない**（§0）

設計どおりに実施した。**結論は反証仮説の否決**で、数値は
[candle_pattern_backtest.md](candle_pattern_backtest.md) §5 にある。ここには
**設計時の見通しと実測がズレた点**だけを記録する。

### 6.1 検出力の低下は見積もりよりずっと小さかった

§2.2 で「CI の広がりは `1/√0.32 = 1.77 倍` より小さくなるはずだが、どこまで小さいかは
実測しないと分からない」と書いた。実測は **1.18 倍（後期）/ 1.24 倍（前期）**。

この結果、§2.2 で最も懸念していた「n 不足でほぼ全行が判定不能になる」事態は起きなかった。
**帯による等価性検定を捨てて CI 上限の報告に切り替えた判断は、結果的には不要だった可能性がある** —
広がりが 2 割なら、既存 88 行の CI 幅から見積もった「±1.0% の帯に 49/88 行」よりずっと多くの行が
帯に収まる。ただし帯を通過率で選べないという §2.2 の論点は消えていないので、上限報告のままとする。

### 6.2 旧 §7 の修正が §3.5 の結論を変えた

**設計時に予期していなかった影響。** 旧 §7（ランダム側の品質フィルタ）を直すと、
§3.5 の旧定義ハンマー（前期 2 行）から ★ が消えた（-0.24% ★ / -0.27% ★ → -0.20% / -0.19%）。

これは §4.4「Phase 3 の仮説はどう決着したか」の**出発点そのものを弱める**。
「旧ハンマーが前期で負に有意だった」という観察の一部が、ランダム側の母集団不一致に
由来していたことになる。§4.4 に追記済み。

**教訓: 既知の欠陥を抱えたまま積み上げた解釈は、欠陥を直すと土台ごと動く。**
§2.1 で「新しい表を足す前に直す」と決めたのは正しかったが、動いたのが新しい表ではなく
**既存の解釈のほう**だった点は見通せていなかった。

### 6.3 品質フィルタをランキング前に置いた効果

§1.6 の決定は実測で裏付けられた。**フィルタを後に掛ける設計だった場合、8303 は
前期の上位 159 に実際に入っていた**（負値を含む系列の `Close × Volume` が上位に来る）。
前に掛けたことで母集団から自動的に外れ、`top` に満たない事態も起きなかった。

### 6.4 実装コスト

パネル計算 4.6 秒の見積もりは正しかったが、**全体の所要時間はそれより
ストアの重複読み込みに支配されていた**。母集団判定・売買代金ランキング・シグナル検出が
同じ Parquet を 3 度読むため、`read_cached` をプロセス内キャッシュとして足して
1 run あたり 18 秒 → 7 秒になった。全 9 run で 1 分強。
