## 0. 目的とスコープ

チャート上に表示しているローソク足パターン（`apps/renderer/src/lib/candlePatterns.ts`）に、
前方リターンの予測力があるかを実測する。N字の検証（[n_pattern_backtest_spec.md](n_pattern_backtest_spec.md)）で
作った OHLCV ストアと統計の枠組みをそのまま流用する。

きっかけは「日足で明けの明星が出た後、1週間後・2週間後の勝率を見たい」という問い。
2026-07 に 7 パターンで測って全否決し、その後 7 種を追加して 14 パターンに増えたため、
2026-08 に**全種を測り直した**のがこの文書の §3 以降である。

**§5 は「小型株のノイズで希釈されているだけで、大型株なら形状に予測力があるのではないか」という
反証仮説への回答である。** §3 の結論は 562 銘柄をプールした平均の上に立っているため、
この反証仮説は否決の後も残っていた。設計の根拠は [large_cap_candle_backtest_spec.md](large_cap_candle_backtest_spec.md)。

## 1. 実装構成

既存の「`analysis/` は純関数・I/O なし / `scripts/` が I/O と探索」という分離を踏襲する。

```
backend/src/analysis/candle_patterns.py   検出器（純関数・14パターン）
scripts/candle_backtest.py                OHLCV 読み込み・前方リターン・ランダム比較・集計
scripts/candle_factor_backtest.py         §4 の形状/文脈の分解（増分検定を含む）
backend/tests/test_candle_patterns.py     84 件
backend/tests/test_candle_backtest.py      7 件（母集団の単一決定点・売買代金ランキング）
backend/tests/test_candle_factor_backtest.py 6 件（分解が検出器からドリフトしないこと）
```

### 1.1 定義はレンダラーと一致させる

閾値（`DOJI_BODY_RATIO=0.1` / `HAMMER_LOWER_RATIO=2.0` / `HAMMER_UPPER_RATIO=0.25` /
`STAR_BODY_RATIO=0.3` / `HARAMI_BODY_RATIO=0.3` / `SIDE_BY_SIDE_OPEN_TOLERANCE=0.005` /
`HAMMER_TREND_LOOKBACK=10` / `HAMMER_TREND_RATIO=0.05` / `ISLAND_MAX_LEN=5`）と
ロジックは `candlePatterns.ts` と同値。

**チャートに描かれるものと検証対象がズレると、検証結果を UI に持ち込めない。**
片方だけ変更してはいけない（変更時は両方 + テストを揃える）。

TS 側に無い `shooting_star` は既存検出器の厳密な鏡像として定義した。**鏡像関係は定数を
書き下すのではなく価格反転（x → -x）でテストしている** — 定義がズレたらテストが落ちる。

**鏡像ペアは 4 つ**（はらみ / 包み / 明星 / アイランド）。**ハンマーと首吊り線は
鏡像ではない** — 形状が完全に同一で、トレンド文脈だけが違う。価格反転すると形状が
流れ星型になる一方、騰落率は分子・分母が同時に符号反転して値が変わらないため、
反転では入れ替わらない（ハンマーの幾何的な鏡像は `shooting_star`）。この 2 種は
価格反転テストではなく排他テストで担保している。

**トレンド文脈のしきい値は日足で較正してある。** `HAMMER_TREND_LOOKBACK = 10` /
`HAMMER_TREND_RATIO = 0.05`（10 本の騰落率で ±5% が概ね 1σ 強）は日足の値幅を前提に
決めた。判定は「本数」ベースでタイムフレームに依存しないため、UI が 5m〜1M で
同じ検出器を走らせると、**分足ではハンマー/首吊り線がほぼ出ず、月足ではほぼすべての
ハンマー型がどちらかに分類される**。この検証と下の実測値はすべて日足のもので、
他のタイムフレームでの較正は行っていない。

**トレンド文脈を見るのは `hammer` / `hanging_man` だけ。** 同型の文脈問題を持つ
`shooting_star`（流れ星／逆ハンマー）は形状のみのままにしてある — UI に出していない
検出器を変更してもユーザーに見える利得が無いため（Phase 6 で解消予定）。
Python 内にこの非対称が残っていることを前提にコードを読むこと。

### 1.2 明星の窓（ギャップ）

古典的な明けの明星は「星が 1 本目の実体より下に窓を開ける」ことを要求するが、
**既定は窓を要求しない**（TS 側の宵の明星に合わせるため）。`--require-gap` で厳密版になる。

**窓の基準はコード内に 2 種類ある。** `require_gap` は**実体基準**（星の実体が 1 本目の
実体の外にあるか）だが、`has_gap_up` / `has_gap_down`（下放れ二本黒・上放れ並び赤・
アイランドが使う）は**高安基準**（ヒゲを含めて重ならない）。見た目の「窓」と一致するのは
後者で、前者は既定 off・UI 経路では未使用のため統一していない。

### 1.3 実装上の注意

- **母集団は `eligible_codes` が 1 箇所で決める。** 品質フィルタをシグナル側とランダム側の
  それぞれで掛ける形に戻さないこと（片方に足し忘れた瞬間に §8 の欠陥が復活する）
- **ランダム母集団は全パターン共通で 1 回だけ抽出する**。パターンごとに引き直すと
  同じ日の帰無分布がパターン間で食い違い、横並び比較が成立しない。
  **1 run = 1 表**。表をまたいでセル単位の比較をしない
- **銘柄ループを外側にする**。パターンごとに全銘柄を読み直すと Parquet の I/O が
  パターン数倍になる。ストアの読み込みは `read_cached` でプロセス内 1 回に抑えてある
- entry は成立バーの**翌営業日始値**、リターンは `close[j+h] / open[j] - 1`。
  `backtest.benchmark_outcome` と同じ規約に揃える（土俵を揃えないと比較できない）。
  **パターン検出も §4 の要素分解も `collect_masked` を通す** — entry の取り方が 1 バーでも
  ズレた系列を混ぜると、差を取る 2 つの平均が別の規約の上で計算される
- **`--seed` を既定の 0 から動かしても表は壊れない**（§8 で修正済み）。ただし本文の
  数値はすべて seed 0 のもの

## 2. 生の勝率を単独で出してはいけない

**2021〜2026 の日本株では、どの銘柄でもいいから 10 日持てば勝率 53〜55% になる。**
市場が上がっているからである。

実測した 14 パターン 56 行の生の勝率は **46.7%〜63.4%**。50% を下回ったのは
**首吊り線の前期 2 行だけ**で、残り 54 行は 50% を超えた。
ランダム比を取らないバックテストツールなら、そのほぼ全部を「有効なシグナル」として報告する。

例:

- 明けの明星 fwd10 は勝率 54.7%。しかし同日ランダムは 56.1% で**負けていた**
- ハンマー fwd10（後期）は勝率 **63.4%** で全 56 行の最高値。ランダムは 57.0% で
  確かに上回っているが、**この差はローソク足の形が生んだものではない**（§4）

→ `scripts/candle_backtest.py` は生の勝率とランダム勝率を必ず並べて出力する。

### 3.3 再現性の点検

**§8 の修正でランダム母集団が 565 → 562 銘柄に変わったため、2026-07 当時の run と
数値が一致することはもう再現性の根拠にならない。** 代わりに次の 2 つで担保する。

1. **検出数がランダム抽選に依らない。** §7 のパターン別検出数（後期・562 銘柄）は
   修正の前後で完全に一致する（ハンマー 4,146 / 首吊り線 6,723 / 同時線 43,684 /
   明けの明星 13,442 / 宵の明星 11,298 を照合済み）。`n` 列も 56 行すべてが修正前と一致する —
   **母集団の変更はランダム側だけに効いており、シグナル側は動いていない**
2. **§4.2 の増分検定 8 行が、スクリプト化前の手作業測定と完全に一致する。**
   この表の対照群は「同じ文脈で形状なし」でランダム抽選を含まないため、§8 の修正の
   影響を受けない。`candle_factor_backtest.py` が手作業の測定を忠実に再現していることの証拠になる

**変わったのは差とランダム勝率と CI の列だけ**で、変化幅は最大 0.1pt 程度である。

**パターンを絞った run と絞らない run を比べるときは注意する。** `random_returns` は run 内の
全シグナル日を昇順に舐めながら単一の `random.Random(seed)` を消費するため、run に含まれる
パターンが変わって日付集合が変われば、以降の抽選がすべてずれる。同時線が事実上すべての
営業日に出るので**同時線を含む run どうしは日付集合が一致する**が、含まない run とは一致しない。

### 4.3 では何を測っていたのか

`HAMMER_TREND_RATIO = 0.05` の条件は、実質的に「直近 10 本で 5% 下げた銘柄を翌日の
寄りで買う」という**短期リバーサル**のフィルタである。ランダム比較の相手は
「同じ日に無条件でランダムに買う」なので、下げた銘柄に絞った時点で差が出る。

これは既知の市場効果であって、ローソク足パターンの検証結果ではない。
[backtest_gotchas.md](backtest_gotchas.md) の
「要素の発火は相場局面と相関するため、生リターンでは要素が効いたのか地合いが良かったのかを
分離できない」と同じ構図が、ここでは「文脈条件」と「形状条件」の間で起きていた。

### 4.4 Phase 3 の仮説はどう決着したか

「旧ハンマーが前期で負に有意だったのは、上昇後の首吊り線を混入させていたからではないか」
という仮説（PRD Q1 / Technical Risks）は、**現象としては支持されるが、前提そのものが
§8 の修正で弱まった。**

- 旧定義（形状のみ）前期: **-0.20% / -0.19%（★ なし）** ← 修正前は -0.24% ★ / -0.27% ★
- 三分化後のハンマー 前期: +0.23% / +0.49%（符号が反転）
- 三分化後の首吊り線 前期: -0.40% ★ / -0.74% ★（弱気パターンとして符号も正しい）

負の寄与が上昇文脈側に集まりハンマーから消える、という**方向性は再現している**。
ただし出発点だった「旧ハンマーの前期の有意性」は、**その一部がランダム側の母集団不一致
（§8）に由来していた**。三分化がその有意性を解消した、という因果の物語はもう成立しない。

**三分化は表示の正しさとしては依然として正解**である（上昇後のハンマー型に強気ラベルを
出すのは、実測でも間違いだった）。ただし §4.2 のとおり、分離できた理由は形状ではなく
文脈条件そのものにある。**「ハンマーに予測力があることが分かった」と読んではいけない。**

## 5. 大型株に絞った再検証

§3 の結論は 562 銘柄をプールした平均の上に立つ。「小型株のノイズで希釈されているだけで、
大型株なら形状に予測力があるのではないか」という反証仮説に答えるための節。
設計の全体は [large_cap_candle_backtest_spec.md](large_cap_candle_backtest_spec.md)。

### 5.1 設計の要点

- **規模の指標は時価総額ではなく売買代金**（`Close × Volume` の 60 本ローリング中央値）。
  ストアは `auto_adjust=True` で過去バーが実株価ではないため過去時点の時価総額は計算できない。
  `Close × Volume` は分割に対して不変で、調整済みストアのままで正しく計算できる唯一の規模指標。
  時価総額スナップショットで絞ると **1兆円超 159 銘柄の 35%（55 銘柄）は 2021 年時点では
  1兆円未満**（フジクラは 39.8 倍）で、勝ち組を後知恵で選ぶことになる
- **上位 159 銘柄**（時価総額 1兆円 ≒ 売買代金 50 億円/日 で 155 銘柄、捕捉率 81%）
- **`shift(1)` で当日を見ない**。各 run の期首で 1 回だけ確定（日次リバランスとの母集団一致率は 78%）
- 前期は先頭 40 営業日がローリング窓を満たさないため、**2021-09-24 のランキングを遡及適用**
  （§3.2 と期間を完全一致させるため。遡及の影響は実測で約 6%）
- **ランダム対照群も同じ 159 銘柄**。シグナル側だけ絞ると「大型株が上がった」を測ることになる
- **品質フィルタはランキングの前**（8303 は負値を含むため売買代金の順位そのものが無意味）

**CI 幅の広がりは中央値で 1.18 倍（後期）/ 1.24 倍（前期）にとどまった。**

素朴な `1/√0.32 = 1.77 倍` よりずっと小さいのは、**ブートストラップの再抽出単位が日付**で
あって銘柄ではないため。同時線が事実上すべての営業日に出るので日付数はほとんど減らず、
減るのは 1 日あたりのシグナル数だけになる。

| 全 562 銘柄・後期 | 0.69pt | 0.49% | 2.07% |

全銘柄では見えていた ★（前期の首吊り線 2 行）が大型株で消えるほどの幅ではない。

### 5.6 大型株の結論

**大型株に絞っても形状に予測力は無い。** 反証仮説は否決される。

- 56 行中 ★ は **2 行**（α=0.05 での偽陽性期待値 2.8 を下回る）。しかもその 2 行は
  どちらも後期のハンマー/首吊り線で、§5.5 のとおり**下降文脈のみで同じ大きさの差が出る**
- **形状の増分は 8 行中 7 行で CI が 0 を跨ぎ、残る 1 行は形状があるほうが悪い**。符号は期間で反転
- **形状の増分の CI 上限は最大 1.38%。** 大型株に絞っても、形状がトレンド文脈に
  上乗せする効果は fwd10 で **±1.4% を超えない**
- 検出力の低下は CI 幅で 2 割程度にとどまり（§5.4）、「n 不足で見えないだけ」とは言えない

**「大型株なら効くのでは」という直感が生まれる理由は §4.3 と同じ**である。大型株の
ハンマーは生の勝率が 62.5% と高く見えるが、同じ日にその 159 銘柄からランダムに買っても
57.1% になる。差の大部分は「下げた銘柄を翌日の寄りで買う」という短期リバーサルであり、
ローソク足の形が寄与している部分は上の上限より小さい。

## 6. 結論

**14 パターンすべて否決。ローソク足の形状に前方リターンの予測力は無い。
これは全 562 銘柄でも、大型株 159 銘柄でも変わらない。**

| 母集団 | 行数 | ★ | 偽陽性期待値 | 内訳 |
|---|---|---|---|---|
| 全 562 銘柄 | 56 | 5 | 2.8 | 後期ハンマー 2 / 前期首吊り線 2 / 前期下放れ二本黒 1 |
| 大型株 159 銘柄 | 56 | 2 | 2.8 | 後期ハンマー 1 / 後期首吊り線 1 |

★ が付いた行の判定:

| 行 | 判定 |
|---|---|
| ハンマー・首吊り線（両母集団） | **形状ではなくトレンド文脈（短期リバーサル）由来**（§4 / §5.5）。形状の増分は CI が 0 を跨ぐ |
| 前期下放れ二本黒 1 行（全銘柄） | 弱気パターンなのに**符号が逆**。後期では有意性が消える。偶然の出方 |

**形状の増分だけを測った 16 行（全銘柄 8 + 大型株 8）で、有意なのは「形状があるほうが悪い」
3 行だけで、その符号はいずれも期間をまたぐと反転する。**
形状の増分の CI 上限は全銘柄で最大 1.10%、大型株で最大 1.38%。
N字の検証（§15.3）や旧ハンマーで見たのと同じ現象である。

この結論は UI の方針を変えない。パターン表示の立場は**中立な観察ツール**であり
（PRD Decisions Log「表示の立場」）、予測力の有無で表示を止める設計ではない。
**否決だからマーカーを消す、という話にはならないし、逆に有意だから勝率を出す、という話にもならない。**

## 8. 修正済みの欠陥: ランダム側の品質フィルタ（旧 §7）

**この欠陥は修正済み。** 記録として残す。

`collect_signals` はシグナル側に品質フィルタを掛けていたが、`random_returns` には
**同じフィルタが無かった**。シグナル側 562 銘柄・ランダム側 565 銘柄で、比較の土俵が
そもそも揃っていなかった（シードに依らない母集団の不一致）。

実害は 8303（上場廃止・再上場を跨いだ系列）で、693 行中 245 行が負値、fwd10 の最大値が
**+1,977万%**。この 1 サンプルがどこかの日付で引かれると、その日の帰無平均が桁ごと壊れる。

**修正**: 品質フィルタを `eligible_codes` に切り出し、`main` が 1 回だけ掛けた結果を
シグナル側とランダム側の**両方に渡す**（母集団の決定点を 1 箇所にする）。
`backend/tests/test_candle_backtest.py::test_signal_and_random_populations_are_identical` が
両者へ渡された `codes` を捕まえて一致を検査する。

修正前後の再現（後期・同時線・fwd10）:

| seed | 修正前の差 | 修正前の 95% CI | 修正後の差 | 修正後の 95% CI |
|---|---|---|---|---|
| 0 | +0.07% | [-0.12%, +0.26%] | +0.04% | [-0.14%, +0.23%] |
| 1 | **-445298.71%** | **[-1335896.32%, +0.19%]** | +0.18% | [-0.02%, +0.40%] |
| 2 | +0.00% | [-0.20%, +0.22%] | -0.08% | [-0.30%, +0.13%] |
| 3 | +0.11% | [-0.10%, +0.31%] | +0.15% | [-0.06%, +0.36%] |

**この修正で §3 以降の数値がわずかに動いた**（変化幅は最大 0.1pt 程度）。
影響を受けたのは差・ランダム勝率・CI の 3 列だけで、`n` と検出数は全行で不変（§3.3）。
**★ の集合は全銘柄では変わらなかった**が、§3.5 の旧定義ハンマー（前期 2 行）からは
★ が消えた — §4.4 の前提が弱まったのはこのため。

**当時「seed 0 なら壊れていない」と判断した根拠にも注意しておく。** 有効だったのは
「差の列が全 56 行で ±1.5% に収まっていること」だけで、次の 2 つは根拠にならなかった:

- **ランダム勝率が 52〜57% に収まっていること** — 勝率は `> 0` を数える符号統計で、
  +1,977万% も +0.1% も 1 勝としか数えない。**外れ値では壊れないので検出できない**
- **過去の run と行が完全一致すること** — 同じ seed・同じ日付集合なら
  **同じように汚染されていても一致する**ので、汚染の不在を示さない

## 10. 新しいパターンを足すとき

1. `analysis/candle_patterns.py` に検出器を書く（純関数・bool 配列を返す・複数バー構成は
   **最終バー位置**に True）
2. `DETECTORS` / `LABELS` / `SIGNALS` の 3 つに登録する
   （テスト `test_labels_and_signals_cover_every_pattern` が揃っていることを保証する）
3. UI にも出すなら `candlePatterns.ts` を同じ定義・同じ閾値で更新する
   （手順の全体は [CLAUDE.md](../../CLAUDE.md) の「ローソク足パターン」節）
4. `scripts/candle_backtest.py` は引数を増やさずそのまま使える

**生の勝率だけで判断しないこと。** この銘柄群・この期間のベースレートは 53〜55% で、
それを明確に超えないパターンは情報を持っていない。

**条件を 2 つ以上持つ検出器を足したら、条件ごとに分けて測ること**（§4 / §5.5）。
形状 + 文脈のように条件を重ねると、どちらが効いているのか合成後の数字からは分からない。
**母集団フィルタ（大型株など）も条件のひとつ**として数える。

**★ は判定ではなく、追検証すべき行の目印である。** 多重検定の補正は掛けていない —
56 行は独立ではなく同じ日付・銘柄・バーを共有しており（同時線は全営業日に出るので
他のすべてのパターンと日付集合が重なる）、独立を仮定した補正は「どれだけ保守的か
分からない」数字になる。代わりに偽陽性期待値と実測数を突き合わせ、★ が付いた行を
1 行ずつ潰す（§6）。
