# KANATA機能追加: N字シグナル バックテスト検証基盤

**ステータス**: 実装済み（§13 のステップ 1〜3・5〜9。ステップ 4「3年で②を実行し検証期間を確定」は実装ではなく実行タスクのため未実施、ステップ 10「本番スキャンの OHLCV ストア切り替え」はスコープ外）
**関連**: [n_pattern_screening_spec.md](n_pattern_screening_spec.md)

---

## 0. 目的

N字スクリーニングで検出した銘柄が、その後実際に上昇トレンドを継続したかを**過去データで実測**する。

**やらないこと**: 検出時点の判断材料を増やす（相対強さ・ファンダ・セクター等を並べた多角チェック画面）。
検証されていない指標を並べても「根拠が増えた気になる」だけで、外れた理由が特定できなくなるため。
表示すべき指標は、本バックテストで有意だったものだけを後から追加する。

**検証対象の前提**: `n_pattern.py` のスコア構成（BASE 40 / TREND 25 / BREAKOUT 15 / VOLUME 10 /
MACD 10 / PULLBACK -15 / DURATION -15 ほか）はすべて経験則で置かれた値であり、実測での裏付けがない。
本基盤の第一の問いは「**今のスコアは機能しているのか**」である。

## 1. 測定対象（正解ラベルの定義）

### 1.1 記録するもの

出口ルールを決めず、シグナルの素の性質を記録する。

| 項目 | 内容 |
|---|---|
| フォワードリターン | 20営業日後・60営業日後の騰落率 |
| MFE | 保有期間中の最大含み益（Maximum Favorable Excursion） |
| MAE | 保有期間中の最大含み損（Maximum Adverse Excursion） |
| days_to_mfe | MFE 到達までの営業日数 |

### 1.2 出口ルール模擬をやらない理由

損切り-8%・利確+15% 等を最初から組み込むと、結果が悪かったときに
「N字シグナルが無効」なのか「損切り幅が浅すぎただけ」なのかを切り分けられない。
シグナル評価と出口ルール評価は別問題として分離する。

MFE/MAE を生で記録しておけば、**出口ルールの検証は再スキャンなしで後から何通りでも回せる**。
出口ルール最適化は本基盤の派生分析として後段で実施する。

## 2. データ基盤

### 2.1 ローカル OHLCV ストアを新設する

```
<KANATA_DATA_DIR>/ohlcv/<symbol>.parquet
```

- 初回に対象期間分を一括取得 → 以降は差分更新
- **バックテストと本番スキャンの両方がこのストアを読む**（本番スキャンの `sleep(0.2)×565銘柄` の待ち時間が消える副次効果）

### 2.2 既存 SQLite（kanata.db）に入れない理由

`kanata.db` はユーザー設定（ウォッチリスト）の永続化領域であり、起動時に7世代バックアップを取る対象。
数百MB級の時系列を同居させるとバックアップコストが跳ね、`init_db` の seed 責務とも混ざる。
時系列は列指向で読むため Parquet が素直。

### 2.3 都度取得（キャッシュなし）を採らない理由

再実行のたびに数十分を要するうえ、yfinance のレート制限に当たると検証が途中で壊れ、
「取得できた銘柄だけの統計」という気づきにくいバイアスが混入する。

### 2.4 実行時間の本丸は取得ではなく検出の再実行

565銘柄 × 数年分を1バーずつ進めて `detect_n_pattern` を再実行すると、概算で数十万〜百万回のコールになる。

**ATR と MACD は因果的（時刻 t の値は t 以前しか参照しない）なので、全期間で一度だけ計算してスライスしても
先読みは発生しない。** ここを毎回再計算しない設計にすることで、実行時間が桁で変わる。

> `detect_n_pattern` は pandas.DataFrame を受け取る純関数（I/O なし）なので、
> `df[:t]` を渡して走らせ直すウォークフォワードは素直に書ける。

## 3. ユニバース

### 3.1 使用するユニバース

`backend/data/topix_universe.csv` — TOPIX の一定ウェイトを超える **565銘柄**（`code, name` の2列）。

`market_cap` 列を持たないため、既存の `load_universe` はそのまま通る
（列欠落 → `None` → 時価総額フィルタ非適用）。

### 3.2 時価総額の過去補正が不要になった経緯

当初は「今日100億円以上」というフィルタを過去に適用することによる**先読みバイアス**が懸念だった。
当時30億円で現在150億円の銘柄＝5倍になった銘柄だけがユニバースに残り、勝率が構造的に上振れる。

本ユニバースは時価総額カットオフを使わないため、この経路のバイアスは発生しない。

### 3.3 残存するバイアスと対処

**残るもの**: 「今日のTOPIXウェイト上位565銘柄」という構成自体の緩やかな先読み。
ただし大型〜中型中心の集合で5年間の入れ替わりは限定的なため、**期間を短く切る（2〜3年）ことで抑制**し、
レポートに注記する。

**生存バイアス（上場廃止銘柄の欠落）について**: 日本株では方向が一意でない。
上場廃止の主因は倒産だけでなく TOB であり、TOB は +30% 級の跳ね上がりを伴う。
欠損しているのは大負けと大勝ちの両方であるため、平均への影響は不明だが、
**分散は確実に過小評価される**（最大ドローダウンが実際より小さく見える形で現れる）。

完全なポイントインタイム・ユニバース（JPX 過去上場一覧の別調達）は、個人アプリのコスト対効果に見合わないため採らない。

## 4. ベンチマーク

**比較対象のないバックテストは、事実上その期間の地合いを測っているだけになる。**
2023〜2024年の日本株は全体が上昇しているため、ランダムに買っても良好な数字が出る。

### 4.1 TOPIX 対比（表示用）

同じ保有期間の TOPIX 騰落率を引いた超過リターンを、レポートの主指標とする。
TOPIX を1本 OHLCV ストアに入れるだけで実装できる。

### 4.2 日付マッチのランダムエントリー（判定用）

各シグナルの発生日について、**同じ日に同ユニバースからランダムに銘柄を選び**同期間保有した場合の
分布をブートストラップで生成し、N字の平均がその分布のどこに位置するかを見る。

- TOPIX 対比だけでは「1%の超過がまぐれの範囲か」を判定できないため必要
- **ユニバース選択自体のバイアスをキャンセルする**（同じ565銘柄から引くため相殺される）
- OHLCV をローカルに持つ設計のため、追加コストはほぼゼロ

### 4.3 ブロックブートストラップにすること

同じ日に複数銘柄が同時にシグナルを出すケース（地合いの良い日にまとめて出る）は互いに独立ではない。
再サンプリングは**銘柄単位ではなく日付単位（日をまるごと引く）**で行う。

## 5. 重複シグナルの排除

### 5.1 同一ブレイクの再検出（記録時に必須で潰す）

`RECENCY_MAX_BARS = 10`（D から末尾まで10バー以内）のため、日を1本ずつ進めるウォークフォワードでは
**同一のブレイクが最大11営業日連続でヒットする**。

素直に記録すると、実質140件のイベントが1,500件のレコードになる。
これは単なるレコード増ではなく、**サンプル数が11倍に水増しされ、ブートストラップの信頼区間が
実際の1/3程度に狭まり、有意でないものが有意に見える**。

→ `(symbol, break_date)` でユニーク化し、初出のみ記録する。
`detect_n_pattern` は既に `break_date` を返しているため実装は容易。

### 5.2 同一銘柄の連続シグナル（フラグで記録し集計時に切替）

ブレイク D が次の N字の A になり、20営業日以内に次のシグナルが出るケースは**本物の別イベント**。
ただし保有期間が重なるため統計的に独立でなく、実運用でも同一銘柄を重ねて建てない。

→ レコードは残したうえで `overlaps_prev: true` のフラグを立て、集計時に含める/含めないを切り替える。
**記録時に消すと後から戻せない**ため、除外は必ず集計側で行う。

## 6. エントリー価格

### 6.1 2種類を記録し、役割を分ける

| entry 種別 | 定義 | 役割 |
|---|---|---|
| `entry_next_open` | ブレイク日の翌営業日始値 | **検定用** — シグナルに情報があるかを問う（§4.2 ブートストラップ、§7 スコア単調性） |
| `entry_weekly` | ブレイク後、最初に到来する金曜の翌営業日（＝月曜）始値 | **主指標** — 期待値の見積もり。レポートの主数字 |

### 6.2 週末スキャン再現を主指標にする理由

実運用のスキャンは**週1回（週末）** で、週の中で1〜2回追加実施する程度。
したがって実際のエントリーはブレイクから 0〜4営業日遅れる。

**ブレイク直後の数日は N字の値動きが最も速い区間なので、この遅延はリターンを大きく削る。**
翌日始値を主指標にすると、構造的に得られない数字を基準に判断することになり、
実運用で下振れしたときに「手法が壊れた」と誤診する。

一方、検定（シグナルに情報があるか）に遅延という運用要因を混ぜると、
シグナルが無効なのか運用が遅いのかを切り分けられなくなる。よって用途で使い分ける。

### 6.3 ブレイク日の終値を使わない理由

終値が確定して初めて N字が成立するため、その同じ終値では買えない（先読み）。
金額差は小さいが、「ブレイクした日の終値」は定義上その日の上昇を織り込んだ後の価格であり、
系統的にリターンを水増しする方向にズレる。

### 6.4 手数料・スリッページは記録時に引かない

後から一律で差し引ける定数（`fwd20 - 0.2%` 等）。
記録段階で混ぜると手数料率を変えるたびに再スキャンが必要になる。
**「生の値を記録し、加工は集計時」という本設計の一貫した方針に従う。**

### 6.5 遅延感応度を出す

エントリーを +1 / +3 / +5 営業日ずらした場合のリターンも併せて集計する。
OHLCV が手元にあるため追加コストは軽微で、
**「遅れて買っても成立する手法か」という実運用上もっとも重要な問いに答えられる。**

## 7. スコアの検証方法

### 7.1 閾値の最適化は行わない

`n_pattern.py` の定数11個（BASE 40 / TREND 25 / BREAKOUT 15 / VOLUME 10 / MACD 10 /
PULLBACK -15 / DURATION -15 / MARGIN 2.0% / RECENCY 10 / ZIGZAG係数 1.5 / TREND_DROP 10%）は
すべて経験則だが、**サンプル数の桁が合わないため最適化しない**。

§5.1 のユニーク化後の独立イベント数は565銘柄・3年でおそらく数百件のオーダー。
仮に600件として11個の連続パラメータを最適化すれば確実にノイズにフィットする。
期間分割（train/test）にしても train が300件では同じ。ウォークフォワード最適化はさらに成立しない。

### 7.2 代わりにやること: スコア帯別の単調性

スコア帯（0-50 / 50-70 / 70-85 / 85-100）ごとに fwd20・fwd60・MFE/MAE を集計し、
**スコアが上がるとリターンが上がるか**だけを見る。

| 結果 | 意味 | 次の一手 |
|---|---|---|
| 単調に上昇 | スコアは機能している | 閾値をいじる必要がそもそもない |
| フラット | スコアはノイズ | 定数の調整ではなく、**スコアという仕組み自体を捨てるか作り直す** |
| 逆転 | どれかの加点要素が有害 | 要素別分析で犯人を特定する |

**いずれのケースでも次の一手は「閾値の微調整」ではない。**
微調整が正解になるシナリオが存在しない以上、最適化機構を作るのは工数の無駄である。

### 7.3 要素別の寄与分析

`score_detail` は既に結果レコードに含まれているため、
**要素別の寄与（例: 出来高ボーナスが付いた群 vs 付かなかった群の fwd20 差）は最適化なしで算出できる。**
これが実質的に「どの要素が効いているか」の答えになる。

### 7.4 例外: RECENCY_MAX_BARS は検証できる

§6.5 の遅延感応度曲線により、`RECENCY_MAX_BARS = 10` の妥当性が直接検証される。
遅延5日以降でリターンがゼロに潰れるなら `RECENCY` は 5 に絞るべき、という具体的な結論が出る。

**11個の定数のうち、これだけはサンプル数の問題なく単独で検証できる**
（連続値の最適化ではなく、遅延という観測可能な軸に沿った素直な集計であるため）。

## 9. 実装構成

### 9.1 レイヤ分割

UI は作らない。既存の「`analysis/` は純関数・I/O なし / `services/` が I/O を担う」分離をそのまま踏襲する。

```
backend/src/services/ohlcv_store.py   ① 取得・保存・読み出し（本番スキャンとも共用）
backend/src/analysis/backtest.py      ②③ ウォークフォワード・MFE/MAE 計算（純関数、I/O なし）
scripts/backtest.py                   ④ 実行・集計・レポート出力（探索的に書き換える層）
```

pytest は既存の `backend/tests/` に乗る（`test_n_pattern.py` と同じ扱い。
MFE/MAE 計算・ユニーク化ロジックは純関数なのでテストしやすい）。

### 9.2 アプリ内に検証タブを作らない理由

日常的に使う機能ではなく、閾値を疑ったときに数回だけ回す**研究作業**である。
それ以上に効くのが探索性で、検証は必ず「スコア帯別 → セクター別 → 地合い別 → 押し目の深さ別」と展開する。
**UI で固定した集計軸は確実に足りなくなり**、そのたびに React・API・スキーマを書き直すのは割に合わない。

`scripts/` を別プロセスで走らせるため、`_scan_state`（モジュールレベルの単一 dict、
`running` 中は 409）との排他問題も発生しない。**検証中も通常のスクリーニングは回せる。**

> **将来アプリに載せる可能性**: 検証の結果スコアが機能していると判明したら、
> スコア帯別の期待値をスクリーニング表に1列足す（「スコア85 → 過去実績 fwd20 +2.4%」）のは価値がある。
> 集計軸が固定されるため UI 向き。ただし**検証が終わってからの話**であり、今作るものではない。

## 10. 実行パイプライン（4段階）

性質もコストも異なるため分割し、各段階の出力をファイルに残して個別に再実行できるようにする。

| 段階 | 内容 | 概算コスト | 再実行頻度 | 出力 |
|---|---|---|---|---|
| ① 取得 | 565銘柄＋TOPIX の OHLCV を Parquet 化 | 数分（初回のみ、以降は差分） | ほぼゼロ | `ohlcv/<symbol>.parquet` |
| ② 検出 | ウォークフォワードで `detect_n_pattern` を再実行し `(symbol, break_date, score, score_detail, pivots)` を確定 | **数十分** | 期間・アルゴリズム変更時 | `backtest/signals.parquet` |
| ③ アウトカム | entry 5種・fwd20/60・MFE/MAE・TOPIX を計算 | 数秒〜数分 | 保有期間・entry 定義の変更時 | `backtest/outcomes.parquet` |
| ④ 集計 | スコア帯別・要素別・ブートストラップ・レポート | 数秒 | **何度も** | レポート |

### 10.1 ② と ③ を分離する理由（速度ではなく正しさ）

**②のループは `df[:t]` を1バーずつ進める「検出のための走査」、③は確定したイベント日から「前方を見る」処理で、
向きが逆である。** 同居させると②のループ内で未来のバーを参照するコードを書くことになり、
**先読みバグが最も混入しやすい形になる。** 分離すれば②のコードは構造的に未来を触れない。

副次的に、③のパラメータ（保有期間90日を見たい／遅延を+7まで伸ばしたい／手数料を変えたい）は
確実に変更するため、分離しないと**そのたびに数十分待つ**ことになり、
§12 の「生の値を記録し加工は集計時」という方針が絵に描いた餅になる。

②の出力は数百行しかないため、**②さえ一度通れば以降の試行錯誤はすべて数秒で回る。**

### 10.2 進捗表示

②のみ `i/565 銘柄` を stderr に出す程度で足りる。
別プロセスの単発スクリプトに `_scan_state` のようなジョブ管理機構は不要。

## 11. 検証期間の決定手順

**まず3年（2023年7月〜）で②を回し、独立イベント数を数えてから確定する。**

### 11.1 必要サンプル数の目安

日本株の20営業日リターンは標準偏差 12% 前後。N字の効果が「ランダム比 +2%」なら効果量 d ≈ 0.17 で、
検出力80%で検出するには**独立イベントが300件強**必要。
これを下回ると、効果が存在しても「有意差なし」で終わる。

→ **§5.1 のユニーク化後のイベント数が200件を切るなら、期間を伸ばす。**

### 11.2 期間を伸ばすコストはバイアスであり、実行時間ではない

3年→5年で②の実行時間は約1.7倍（数十分→1時間強）だが一度きりなので問題にならない。
問題は §3.3 の「今日のTOPIXウェイト上位565銘柄」という構成の先読みが、遡るほど効くこと。

### 11.3 ただし主目的は期間短縮の影響を受けにくい

§4.2 の日付マッチのランダムエントリーは、同じ日に同じ565銘柄から引くため
**ユニバース選択バイアスが相殺される。**

| 問い | ユニバースバイアス | 必要期間 |
|---|---|---|
| N字はランダムより優れているか（**主目的**） | 相殺される | 短くてよい |
| 絶対リターンはいくらか | 乗る | 長い期間が要る |

### 11.4 5年を選ぶ場合の唯一の動機は下落相場

2〜3年では2024年8月の急落を含む程度で、**継続的な下落局面での挙動が測れない。**
「N字は上昇相場でしか効かない」は十分あり得る結論であり、実運用上の重要度は高い。
5年（2021年7月〜）なら2022年の世界的利上げ局面が入る。

→ **イベント数が足りていれば3年、足りない／下落局面を見たい場合は5年。**

## 12. 設計方針（通底するルール）

1. **生の値を記録し、加工は集計時に行う。** 手数料・出口ルール・重複除外・期間フィルタは
   すべて後段で切り替えられるようにする。再スキャンを要求する設計にしない。
2. **シグナル評価と運用条件を混ぜない。** 検定は理想条件（翌日始値）、期待値は実運用条件（週末スキャン）。
3. **サンプル数に見合わない自由度を導入しない。** 数百件のイベントで11パラメータを最適化しない。
4. **比較対象のない数字を出さない。** 絶対リターン単独では地合いと区別できない。
5. **未来を参照できないコード構造にする。** 先読みは注意力で防がず、レイヤ分割で構造的に不可能にする（§10.1）。

## 14. 検証結果（2026-07）

期間 2023-07-03 〜 2026-07-29、563 銘柄、独立イベント **6348 件**。
§11.1 の目安（300 件強）を大きく超えており、**検出力不足ではない**。

### 14.1 結論: 優位は検出できなかった

| 比較 | 結果 |
|---|---|
| N字 vs ランダムエントリー（判定用・生 fwd20） | **-0.13%**（95% CI [-0.58%, +0.33%]、片側 p = 0.711） |
| N字 vs TOPIX（超過リターン） | +0.73% |

**TOPIX 比の +0.73% を「勝ち」と読んではいけない。** ランダムエントリーも TOPIX を
約 +0.87% 上回っており、これは 563 銘柄を等加重で買ったことによる超過（時価総額加重の
TOPIX に対する等加重プレミアム）であって、シグナルの寄与ではない。
**§4.2 でランダム比較を入れた理由がここで実証された** — TOPIX 比だけを見ていたら
勝ったと誤読していた。判定に使うのはランダム比のみ。

### 14.2 データ品質の欠陥を 2 つ発見した

**① ベンチマーク（1306）のスケール異常**。2026-03-30/31 の 2 本が 1/10 になっており、
`partition_by_quality` はユニバース銘柄しか検査していなかったためすり抜けた。
**ベンチは全シグナルの超過リターンに入る単一障害点**で、58 行（全体の 0.9%）が
excess を -970% にして**集計全体の平均を -0.57% と +0.72% の間で符号ごと裏返した**。
**歪度が -19.9 に振れていたのが唯一の目印だった**（中央値と勝率はほとんど動かない）。
→ `benchmark_bad_dates` / `contaminated_entry_dates` を追加。

**② ユニバース銘柄の判定は 3 件中 1 件が誤検出**だった。

| 銘柄 | 日次変化 | 判定 | 根拠 |
|---|---|---|---|
| 8227 しまむら | -66.4% | **データ不良** | 値幅制限（¥11,000 帯は ±¥3,000 ≒ ±27%）を超える＝取引所ルール上不可能。価格比 1/2.97、出来高 7.6 倍、調整の切れ目が小数/整数で見える |
| 6632 JVCケンウッド | +37.0% | **実データ** | ¥200-500 帯の値幅制限 ±¥80 の**範囲内**。出来高 14.5 倍、翌日以降も +8.1%/+6.6% と続伸し水準が戻らない |
| 8303 SBI新生銀行 | 各種 | データ不良 | 負値・25 兆円の Close・782 日ギャップ |

`SANITY_MAX_DAILY_RETURN = 0.30` の一律%は**両端で外す**（¥201 では ±40% が合法、
¥11,000 では ±27% が上限）。東証の制限値幅テーブル（15 行程度）を使えば
ヒューリスティックではなく厳密な判定になる。**未実装**。

### 14.3 要素別の寄与（超過リターン基準）

**生 fwd20 で見てはいけない。** 要素の発火は相場局面と相関するため、
生リターンでは「要素が効いた」のか「その要素が出やすい時期の地合いが良かった」のかを
分離できない。実測で `sd_volume` が生 +0.16% → 超過 -0.05% と符号ごと変わった。

| 要素 | 重み | 差（超過） | 中央値の差 | 判定 |
|---|---|---|---|---|
| `sd_trend` | +25 | **-0.65%** | -0.19% | 有意に負 → **0 にした** |
| `sd_pullback_penalty` | -15 | **+1.63%** | +1.77% | **有意に正（符号が逆）** |
| `sd_macd` | +10 | +0.46% | +0.19% | 有意でない |
| `sd_breakout` | +15 | +0.35% | +0.33% | 有意でない |
| `sd_volume` | +10 | -0.05% | -0.18% | 有意でない |
| `sd_duration_penalty` | -15 | n/a | n/a | **3 年で発火 1 件＝死にコード** |

**多重比較に注意**: 5 要素を検定して 2 つが有意、どちらも CI が辛うじて 0 を外す水準。
Bonferroni（α=0.01）ではどちらも残らない。**確定した効果ではなく有望な仮説**。

`sd_pullback_penalty` だけが平均・中央値・1% トリム後のすべてで一貫している。
「押し目が浅い＝押し目として機能していない」という当初の仮説に対し、実測は
「浅い＝需給が強い」を示唆する。ただし発火は 255 件（4%）のみ。

### 14.4 スコア帯の逆行は減点群が作っていた

§2 の逆行（最下位帯が最高）は `pullback_penalty` 群がそこに集中していることの反映。
減点群（n=255）を分離して切り直すと**逆行が消え、弱い単調増加になる**。

| band | n | 平均 | 中央 | 勝率 |
|---|---|---|---|---|
| 40-50 | 2598 | +0.58% | -0.20% | 48.7% |
| 50-60 | 1339 | +0.38% | -0.39% | 47.1% |
| 60-65 | 1053 | +0.92% | +0.12% | 50.5% |
| 65-75 | 774 | +1.05% | +0.08% | 50.8% |

平均・中央値・勝率が同じ向きに揃うのは良い兆候だが、**最上位帯でも中央値 +0.08%・
勝率 50.8% で実用的な大きさではない**。

### 14.5 遅延は劣化を生まない（が、それは悪い知らせでもある）

next_open 2.11% → lag_3 2.38% → lag_5 2.34% → weekly 2.25%。

実運用としては朗報（週末スキャンで損をしていない）。しかし仮説としては悪い知らせで、
**本物のブレイクアウト momentum があるならブレイク直後が最も有利なはず**。
フラットということは、ブレイク日という特定のタイミングに固有の優位が存在しない。
`RECENCY_MAX_BARS = 10` を絞る根拠は無い。

### 14.6 発生頻度が高すぎる

独立イベント 6348 件 ÷ 735 営業日 = **1 日あたり 8.6 件**。20 日保有なら常時 170 銘柄で、
**ユニバースの約 30% が常にシグナル状態**。これは選別として機能しておらず、
実質的に市場そのものを買っている。超過リターンがほぼ 0 なのは当然の帰結。

### 14.7 絞り込みの軸を探したが、機能するものは見つからなかった

頻度を下げつつ質を上げる軸を、パターンの幾何量と外部変数の両方で探した。
**五分位に切って平均・1% トリム平均・中央値・勝率の 4 指標を見た結果、
単調な関係を持つ変数は 1 つも無かった。**

| 軸 | 結果 |
|---|---|
| ブレイク幅 `(D-B)/B` | 非単調（Q4 が最良、Q5 で落ちる） |
| 第一波の高さ `(B-A)/A` | 非単調（Q4 が最良、Q5 で落ちる） |
| 押し目からの上げ `(D-C)/C` | ノイズ |
| A→D の期間 | 弱い減少（短いほど良い）だが Q5 で反転 |
| 押し目の深さ `pullback_ratio` | フラット |
| 同日の同時シグナル数（混雑度） | 地合いと交絡。独立な情報なし |

**「Q5 ではなく Q4 が最良」が複数の変数で出るのはノイズの典型的な兆候**である
（本物の単調効果なら Q5 が最良になる）。

### 14.8 地合いフィルタは正しいベンチマークで消えた（重要な教訓）

唯一 TOPIX 比で 4 指標すべてが単調だったのが**シグナル日時点の TOPIX 直近 60 日
リターン**（地合い）だった。中央値 -0.94% → +0.39%、勝率 45.2% → 52.7% と綺麗に並ぶ。

しかし**同じ地合い区分でランダムエントリーと比較すると構造が消える**。

| 地合い五分位 | N字 fwd20 | ランダム fwd20 | 差 |
|---|---|---|---|
| Q1 (-1.9%) | +2.03% | +2.43% | -0.41% |
| Q2 (+4.2%) | +0.39% | +0.62% | -0.23% |
| Q3 (+8.3%) | +3.32% | +2.24% | **+1.08%** |
| Q4 (+11.4%) | +3.53% | +3.11% | +0.42% |
| Q5 (+15.5%) | +2.39% | +2.25% | +0.14% |

単調性は失われ、Q3 だけが突出する形になる（しかも Q3〜Q5 はランダム側のサンプルが
少なく推定が粗い）。**TOPIX 比で見えていた単調性は、等加重プレミアムが地合いで
変動していただけだった。**

> **これは §14.1 と同じ罠を 2 度踏んだということ。** TOPIX 比で良く見えた構造が
> ランダム比で消えるパターンは繰り返し起きる。**絞り込み軸の評価は必ずランダム比で行う。**

### 14.9 打ち切り判断

ここまでで検定した変数は**12 個以上**（スコア要素 5 + 幾何量 5 + 地合い + 混雑度）。
α=0.05 で 12 回検定すれば、**効果が皆無でも 1 つは「有意」が出る**期待値になる。
これ以上の探索は偽陽性を拾いに行く作業であり、**打ち切るのが正しい**。

残る未検証の方向は 3 つあるが、いずれも先に**ランダム側の同一指標**を用意しないと
同じ罠を踏む。

1. **出口ルール**（§1.2 で後段送りにしたもの）。MFE 平均 ≒ 18%、MAE 平均 ≒ -9% で
   比率は約 2:1 あり、固定期間リターンが 0 でもトレーリングストップなら期待値が
   出る可能性がある。**ただし MFE/MAE はランダムエントリー側で計算していない** —
   どんな銘柄でも MFE は正になるので、比較対象なしに「2:1 だから有利」と読むと必ず誤る
2. **ホライズン**。fwd20/fwd60 以外（5 日、120 日）は未検証
3. **銘柄属性**（流動性・時価総額・セクター・ファンダ）。パターン外の情報で、
   `/api/fundamentals` が既にある

## 15. 週足ボリンジャー中央線フィルタの検証と否決（2026-07）

### 15.1 仮説

「週足で上昇していて、ボリンジャーバンドの中央線（＝週足 20SMA）で反発したもの」に絞る。
**ユーザーの事前仮説**であり、§14.9 で列挙した後付け探索とは統計的な立場が異なる。

判定は押し目 C の時点で行う（C は break_date より前なので先読みにならない）。

- 週足で上昇 = 週足 20SMA の 4 週スロープ > 0
- 中央線からの位置 = `C の終値 / 週足20SMA - 1`

### 15.2 In-sample（2023-07〜2026-07、独立 6008 件）

**仮説の半分は当たり、半分は正反対だった。**

週足 20SMA 上向きは効いた（差 +0.28% → +0.49%）。一方、中央線**付近**は六分位で最悪
（勝率 45.8%）で、良かったのは**中央線に触れずに離れて上にある**群（乖離 +15.3% で
勝率 53.1%）。`sd_pullback_penalty` の符号逆転（§14.3）と同じ方向を別の測り方で見た形。

| フィルタ | 件数 | 差 | 95% CI |
|---|---|---|---|
| (A) 全シグナル | 38.3/週 | +0.28% | [-0.19%, +0.77%] |
| (B) 20SMA 上向き | 28.3/週 | +0.49% | [-0.12%, +1.02%] |
| **(C) 上向き + 中央線で反発** | 8.5/週 | +0.15% | [-0.49%, +0.77%] |
| (D) 上向き + 中央線の上 +5% | 13.5/週 | +0.97% | **[+0.25%, +1.72%]** |
| (E) 上向き + 中央線の上 +10% | 6.9/週 | **+1.30%** | **[+0.31%, +2.33%]** |
| (F) E + 浅い押し目 | 4.3/週 | +1.02% | **[+0.05%, +2.11%]** |

ランダム比で CI が 0 を跨がなかった**唯一の軸**であり、同時に頻度も 38 → 6.9 件/週に
落ちて §14.6 の問題も解いていた。**ただし +5%/+10% の閾値は六分位表を見た後に選んだもの**で、
事前登録されていたのは (C) のほうだった。

### 15.3 Out-of-sample（2021-08〜2023-06、独立 2510 件）で全滅

閾値を一切変えずに別期間へ適用した。期間の TOPIX は +25.0%、最大 DD -16.1%。

| フィルタ | 件数 | 差 | 95% CI | 勝率 | in-sample との比較 |
|---|---|---|---|---|---|
| (A) 全シグナル | 26.1/週 | -0.18% | [-0.70%, +0.32%] | 48.0% | ≒ 0 のまま |
| (B) 20SMA 上向き | 15.6/週 | -0.25% | [-0.85%, +0.33%] | 46.6% | +0.49% → 符号反転 |
| (C) 中央線で反発 | 6.8/週 | +0.13% | [-0.54%, +0.83%] | 46.8% | ≒ 0 のまま（一貫） |
| (D) 中央線の上 +5% | 5.2/週 | -0.38% | [-1.38%, +0.60%] | 45.0% | +0.97% → **符号反転** |
| (E) 中央線の上 +10% | 2.1/週 | **-0.78%** | [-2.22%, +0.62%] | **42.1%** | +1.30% → **符号反転** |
| (F) E + 浅い押し目 | 1.3/週 | -0.98% | [-2.62%, +0.81%] | 41.7% | +1.02% → **符号反転** |

**単に「有意でなくなった」のではなく、点推定の符号が反転し、順序が完全に入れ替わった。**
in-sample では絞るほど良くなった（A +0.28 → E +1.30）が、
out-of-sample では**絞るほど悪くなる**（A -0.18 → E -0.78）。勝率も 52.5% → 42.1%。

n=197（E）は小さく検出力は低いが、**符号反転とフィルタ順序の完全な逆転は検出力では
説明できない**。教科書的な in-sample 過学習であり、§7.1 で「数百件のサンプルで
パラメータを最適化すればノイズにフィットする」と書いたことがそのまま起きた。

### 15.4 結論

- **(D)(E)(F) は否決。** 六分位表を見てから閾値を選んだ時点で、それは検証ではなく当てはめだった
- **(C)（ユーザーの事前仮説）は両期間で ≒ 0。** 唯一挙動が安定していたのがこれ、という皮肉な結果
- **(A) も両期間で ≒ 0**（+0.28% / -0.18%、どちらも CI が 0 を跨ぐ）。
  **独立した 2 期間で基礎シグナルに優位が無いことが確認された**

§14 の結論はより強固になった。**N字パターンには、フィルタで救い出せる優位は無い。**

### 15.5 この検証基盤が回収したもの

(E) は in-sample だけを見れば「差 +1.30%、CI が 0 を外れ、頻度も週 6.9 件で実運用可能」
という、**そのまま本番に入れたくなる結果**だった。out-of-sample を回さなければ
入っていた。§9 で「探索的に書き換える層」を `scripts/` に分離し、
OHLCV を 5 年分持っておいた（§2.1）ことが、ここで直接効いた。

**閾値を後から選んだ仮説は、必ず別期間で確認する。**

## 16. 日足ボリンジャー中央線での再検証と打ち切り（2026-07）

§15 は**週足** 20SMA を中央線に使った。ボリンジャーバンドの標準は 20 期間なので、
日足チャートなら **20日SMA** が中央線になる。別物なので日足でも測り、2×2 を埋めた。

判定は押し目 C の時点、`C の終値 / 日足20SMA - 1`。

| フィルタ | 2021-08〜2023-06 | 2023-07〜2026-07 |
|---|---|---|
| (A) 全シグナル | -0.38% [-0.88, +0.10] | +0.29% [-0.23, +0.77] |
| (G) 中央線 ±3% | -0.38% [-0.90, +0.16] | +0.08% [-0.42, +0.59] |
| **(H) 中央線 ±1.5%** | **-0.68% [-1.30, -0.08] ★** | +0.26% [-0.29, +0.82] |
| (I) G + 高値をわずかに超過 | -0.41% [-0.95, +0.15] | -0.06% [-0.56, +0.47] |
| **(J) 中央線を 3% 以上 下抜け** | -0.24% [-1.01, +0.58] | **+0.90% [+0.19, +1.64] ★** |

**2 つの期間が正面から矛盾する。** (H) は同じフィルタで符号が反転し、前期では
「有意に負」だった。六分位も、前期は中央線付近が最悪（勝率 44.8%）だったのに
後期は最良（51.3%）。

### 16.1 22 検定の較正

週足ラウンド 6 フィルタ × 2 期間 = 12、日足ラウンド 5 × 2 = 10、計 **22 検定**。
α=0.05 での偽陽性期待値は **1.1**。実際に出た「有意」は **2**。しかも 2 つは
別のフィルタ・別の期間で、方向も揃っていない。

**これは効果がゼロのデータから期待される出方そのものである。**
§15.2 の (E) が out-of-sample で反転したのも同じ現象で、
N字周りで拾える「有意」はこの精度では全部この水準だと確定した。

### 16.2 打ち切りと位置づけの変更

N字の検証はここで打ち切る。**N字は「期待値のあるスクリーナー」ではなく
「候補を眼で見つけるための発見ツール」として位置づける。**

スコアによる順位付けには、実測で裏付けられた期待値の含意が無い。
UI にスコアを出し続けるなら、それが「N字らしさの度合い」であって
「期待リターンの高さ」ではないことが読み手に伝わる必要がある（未対応）。

### 16.3 この検証全体が回収したもの

- ベンチマークのスケール異常（§14.2）を発見し、集計の符号反転を防いだ
- TOPIX 比で良く見えた構造が**等加重プレミアム**だった罠を 2 度検出した（§14.1 / §14.8）
- in-sample で「差 +1.30%、CI が 0 を外れ、週 6.9 件で実運用可能」という
  **そのまま本番に入れたくなる結果**を、out-of-sample で棄却した（§15.3）

ローソク足パターンへの適用は [candle_pattern_backtest.md](candle_pattern_backtest.md) を参照。
