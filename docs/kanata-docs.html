共通仕様

ベースURL

http://localhost:8000   // 開発
<動的ポート>             // プロダクション（Electron sidecar）

環境変数 VITE_API_URL で上書き可能。プロダクションでは window.kanata.getBackendUrl() IPC 経由で取得。

レスポンスエンベロープ

Watchlists / Search エンドポイントは共通エンベロープを返す。Quotes / Fundamentals はエンベロープなしで直接配列を返す（例外）。

  data: T | null;       // 失敗時 null
  error: string | null;  // 成功時 null
}

7. マクロ経済指標

ベースパス /api/macro/。全エンドポイント共通クエリ start / end（ISO 日付、省略時は既定 730 日前〜当日）。{success, data, error} エンベロープは使わず、生オブジェクトを直接返す（Quotes / Fundamentals / Screening と同じ方針）。キャッシュキーは macro:{name}:{start}:{end}、TTL は全指標共通で 1時間（_DASHBOARD_TTL_SECONDS = 3600）。

7-1. 個別指標

エンドポイントindicator内容
GET /api/macro/hy-oashy_oasハイイールド債 OAS スプレッド（FRED BAMLH0A0HYM2）
GET /api/macro/net-liquiditynet_liquidityFed 純流動性（WALCL − RRPONTSYD − WTREGEN、兆$ 表示）
GET /api/macro/rsp-spyrsp_spyRSP/SPY 比率（等金額加重 vs 時価総額加重、市場の内側の強さ）
GET /api/macro/nikkei-spnikkei_sp日経平均トレンド（表示専用・momentum 系）
GET /api/macro/nikkei-topixnikkei_topix日経平均/TOPIX 比（表示専用・momentum 系）
GET /api/macro/brent-wtibrent_wtiBrent/WTI 原油スプレッド（表示専用・momentum 系）

レスポンス 200（エンベロープなし）

typescripttype Signal = 'green' | 'yellow' | 'red' | 'gray';

  date: string;
  value: number;
  change: number | null;
  provisional: boolean;
}

  source: string;
  stale: boolean;    // FRED取得失敗時、直近14日以内のキャッシュ値で代替した場合 true
  available: boolean; // FRED_API_KEY 未設定など取得不能時 false

  indicator: string;

  lens: string;

FRED バックエンドの3指標（hy_oas / net_liquidity の WALCL・RRP・TGA）は FRED_API_KEY 未設定でも 500 を返さず、該当指標を meta.available=false, signal="gray" で返す（部分稼働）。rsp_spy と日本株/原油系3指標は yfinance のみで完結するためキー不要。

7-2. 総合ダッシュボード

GET /api/macro/dashboard

レスポンス 200（エンベロープなし）

typescriptinterface DashboardResponse {
  overall_signal: Signal;
  indicators: IndicatorResponse[]; // hy_oas, net_liquidity, rsp_spy, nikkei_sp, nikkei_topix, brent_wti の順
}

overall_signal は hy_oas / net_liquidity / rsp_spy の3指標（コア）のみから算出される。nikkei_sp / nikkei_topix / brent_wti（momentum 系の追加3指標）は表示専用で総合シグナルには寄与しない。判定ルール: 利用可能な指標が0件 → gray。いずれか red → red（red_if_any_red）。yellow が2件以上 → yellow（yellow_if_yellow_count_gte）。それ以外 → green。

閾値設定（config/macro_thresholds.json）

シリーズ ID・ルックバック期間・閾値は JSON で外出し。ハードコード禁止、変更は JSON 編集のみ（MACRO_CONFIG_PATH 環境変数で差し替え可）。

8. N字スクリーニング

ベースパス /api/screening/。Macro 同様 {success, data, error} エンベロープなし、エラーは HTTPException + detail。真実源はキャッシュ済み結果 JSON ファイル（<KANATA_DATA_DIR>/n_pattern_results.json）であり、スキャン進捗（ジョブ状態）はプロセスのメモリ内のみで管理される（アプリ再起動で idle に戻る）。

8-1. 結果取得

GET /api/screening/n-pattern?min_score={n}

クエリ min_score（デフォルト 50）でキャッシュ済み結果をフィルタして返す。スキャン未実行時は空配列。

CSV バリデーション制約

制約値
必須列code のみ（name 欠落時は code 代用、market_cap 欠落/空欄はフィルタ非適用）
最大サイズ2MB（MAX_CSV_BYTES）
最大行数10,000行（MAX_ROWS）
code 列ASCII のみ（非 ASCII は 400）、BOM 自動除去
名前重複内蔵デフォルト名と登録済み名を含めて一意（409）
HTTP原因
400UniverseValidationError（CSV不正）/ BuiltinUniverseError（内蔵デフォルト削除試行）
404UniverseNotFound（未知の universe_id）
409DuplicateUniverseName（同名ユニバースが既存）

スキャン定数: 最低時価総額 DEFAULT_MIN_MARKET_CAP = 100億円、yfinance レート制限対策の待機 SCAN_SLEEP_SECONDS = 0.2秒/銘柄、サムネイル終値本数 CLOSES_TAIL = 120。

エラーハンドリング（フロントエンド）

watchlistApi.ts の unwrap() は以下の順でエラーを処理する：

  1. res.ok === false → res.json().detail または statusText をメッセージに Error を throw
  2. body.success === false → body.error をメッセージに Error を throw
  3. body.data === null → "API returned unsuccessful response" を throw

Quotes / Fundamentals / Search エンドポイントのエラーは呼び出し元で個別にハンドリング。

10. 設定・FREDキー管理

sequenceDiagram participant TP as TweaksPanel participant AK as ApiKeyField participant IPC as ipc/bridge.ts participant SEC as lib/secrets.ts participant SS as Electron safeStorage (DPAPI) participant SC as pythonSidecar.ts TP->>AK: 表示 AK->>IPC: FRED_KEY_STATUS IPC->>SEC: 設定状態確認 SEC-->>AK: {configured, encryptionAvailable} AK->>IPC: FRED_KEY_SET(key) IPC->>SEC: safeStorage.encryptString(key) SEC->>SS: fred-api-key.bin へ暗号化保存 IPC->>SC: restartSidecar() AK->>IPC: FRED_KEY_CLEAR IPC->>SEC: fred-api-key.bin 削除 IPC->>SC: restartSidecar()

FRED キーは平文フォールバックせず、safeStorage.isEncryptionAvailable() が false の場合は保存を拒否する。設定・削除のいずれも restartSidecar() をトリガーし、新しい環境変数でサイドカーを再起動する。
