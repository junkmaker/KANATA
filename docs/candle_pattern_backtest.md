**ステータス**: 検証完了 / 全パターン否決
**関連**: [n_pattern_backtest_spec.md](n_pattern_backtest_spec.md)（方法論の本体はこちら）

---

## 0. 目的とスコープ

チャート上に表示しているローソク足パターン（`apps/renderer/src/lib/candlePatterns.ts`）に、
前方リターンの予測力があるかを実測する。N字の検証（[n_pattern_backtest_spec.md](n_pattern_backtest_spec.md)）で
作った OHLCV ストアと統計の枠組みをそのまま流用する。

きっかけは「日足で明けの明星が出た後、1週間後・2週間後の勝率を見たい」という問い。
検証の過程で TS 側に明けの明星が実装されていないことが分かり、宵の明星の鏡像として追加した。

## 1. 実装構成

既存の「`analysis/` は純関数・I/O なし / `scripts/` が I/O と探索」という分離を踏襲する。

```
backend/src/analysis/candle_patterns.py   検出器（純関数・14パターン）
scripts/candle_backtest.py                OHLCV 読み込み・前方リターン・ランダム比較・集計
backend/tests/test_candle_patterns.py     84 件
```

**§3 の結果表は検証当時の 7 パターンぶん。** その後 Phase 1〜3 で 7 種
（はらみ 2 種・下放れ二本黒・上放れ並び赤・首吊り線・アイランド 2 種）を追加しており、
追加分の検証は未実施。

**さらに §3 のハンマー行は旧定義（形状のみ）の測定値で、現行の実装とは別物。**
Phase 3 でトレンド文脈による三分化（下降後＝ハンマー / 上昇後＝首吊り線 /
横ばい＝どちらも出さない）を入れたため、検出母集団が変わっている。
実測で後期のハンマーは 31,708 件 → 4,144 件（首吊り線が 6,706 件）に減り、
**旧ハンマーの約 66% が ±5% の帯に落ちていた**（10 本の騰落率で ±5% は概ね 1σ 強）。
前期でハンマーが「強気パターンなのに負に有意」（-0.24% / -0.27%）だった異常は、
上昇後の首吊り線が混入していたことで説明できる可能性があり、Phase 5 の再測は
この仮説の検証を兼ねる。**旧結果と新結果を同じ表に並べてはいけない。**

### 1.1 定義はレンダラーと一致させる

閾値（`DOJI_BODY_RATIO=0.1` / `HAMMER_LOWER_RATIO=2.0` / `HAMMER_UPPER_RATIO=0.25` /
`STAR_BODY_RATIO=0.3`）とロジックは `candlePatterns.ts` と同値。

**チャートに描かれるものと検証対象がズレると、検証結果を UI に持ち込めない。**
片方だけ変更してはいけない（変更時は両方 + テストを揃える）。

TS 側に無い `morning_star` / `bearish_engulfing` / `shooting_star` は、既存検出器の
厳密な鏡像として定義した。**鏡像関係は定数を書き下すのではなく価格反転（x → -x）で
テストしている** — 定義がズレたらテストが落ちる。

**鏡像ペアは 4 つ**（はらみ / 包み / 明星 / アイランド）。**ハンマーと首吊り線は
鏡像ではない** — 形状が完全に同一で、トレンド文脈だけが違う。価格反転すると形状が
流れ星型になる一方、騰落率は分子・分母が同時に符号反転して値が変わらないため、
反転では入れ替わらない（ハンマーの幾何的な鏡像は `shooting_star`）。この 2 種は
価格反転テストではなく排他テストで担保している。

**トレンド文脈のしきい値は日足で較正してある。** `HAMMER_TREND_LOOKBACK = 10` /
`HAMMER_TREND_RATIO = 0.05`（10 本の騰落率で ±5% が概ね 1σ 強）は日足の値幅を前提に
決めた。判定は「本数」ベースでタイムフレームに依存しないため、UI が 5m〜1M で
同じ検出器を走らせると、**分足ではハンマー/首吊り線がほぼ出ず、月足ではほぼすべての
ハンマー型がどちらかに分類される**。この検証と下の実測値はすべて日足のもので、
他のタイムフレームでの較正は行っていない。

**トレンド文脈を見るのは `hammer` / `hanging_man` だけ。** 同型の文脈問題を持つ
`shooting_star`（流れ星／逆ハンマー）は形状のみのままにしてある — UI に出していない
検出器を変更してもユーザーに見える利得が無いため（Phase 6 で解消予定）。
Python 内にこの非対称が残っていることを前提にコードを読むこと。

### 1.2 明星の窓（ギャップ）

古典的な明けの明星は「星が 1 本目の実体より下に窓を開ける」ことを要求するが、
**既定は窓を要求しない**（TS 側の宵の明星に合わせるため）。`--require-gap` で厳密版になる。

**窓の基準はコード内に 2 種類ある。** `require_gap` は**実体基準**（星の実体が 1 本目の
実体の外にあるか）だが、`has_gap_up` / `has_gap_down`（下放れ二本黒・上放れ並び赤・
アイランドが使う）は**高安基準**（ヒゲを含めて重ならない）。見た目の「窓」と一致するのは
後者で、前者は既定 off・UI 経路では未使用のため統一していない。

### 1.3 実装上の注意

- **ランダム母集団は全パターン共通で 1 回だけ抽出する**。パターンごとに引き直すと
  同じ日の帰無分布がパターン間で食い違い、横並び比較が成立しない
- **銘柄ループを外側にする**。パターンごとに全銘柄を読み直すと Parquet の I/O が
  パターン数倍になり、7 パターンで実用的な時間を超える
- entry は成立バーの**翌営業日始値**、リターンは `close[j+h] / open[j] - 1`。
  `backtest.benchmark_outcome` と同じ規約に揃える（土俵を揃えないと比較できない）

## 2. 生の勝率を単独で出してはいけない

**2021〜2026 の日本株では、どの銘柄でもいいから 10 日持てば勝率 53〜55% になる。**
市場が上がっているからである。

実測した 7 パターンの生の勝率は **51.7%〜57.3%** で、**全パターンが 50% を超えた**。
ランダム比を取らないバックテストツールなら、全部を「有効なシグナル」として報告する。

例: 明けの明星 fwd10 は勝率 54.7%。しかし同日ランダムは 55.3% で**負けていた**。

→ `scripts/candle_backtest.py` は生の勝率とランダム勝率を必ず並べて出力する。

## 4. 結論

**7 パターンすべて否決。** 28 行（7 パターン × 2 ホライズン × 2 期間）のうち
CI が 0 を外れたのは 2 行のみ。α=0.05 での偽陽性期待値 1.4 に対し実測 2 で、
**効果ゼロのデータから期待される出方そのもの**である。

しかもその 2 行は**強気パターン（ハンマー）が負に有意**という、パターンの意味と逆向き。
さらに後期のハンマーは +0.09% / +0.19% と**符号が反転している**。
N字の検証（§15.3）で見たのと同じ、期間をまたぐと反転する現象。

## 5. 再現方法

```bash
python scripts/candle_backtest.py --horizons 5,10 --start 2023-07-01
python scripts/candle_backtest.py --horizons 5,10 --start 2021-08-01 --end 2023-06-30
python scripts/candle_backtest.py --patterns morning_star --require-gap   # 古典的定義
```

OHLCV ストアが前提（`python scripts/backtest.py fetch --period 5y`）。

## 6. 新しいパターンを足すとき

1. `analysis/candle_patterns.py` に検出器を書く（純関数・bool 配列を返す・複数バー構成は
   **最終バー位置**に True）
2. `DETECTORS` / `LABELS` / `SIGNALS` の 3 つに登録する
   （テスト `test_labels_and_signals_cover_every_pattern` が揃っていることを保証する）
3. UI にも出すなら `candlePatterns.ts` を同じ定義・同じ閾値で更新する
4. `scripts/candle_backtest.py` は引数を増やさずそのまま使える

**生の勝率だけで判断しないこと。** この銘柄群・この期間のベースレートは 53〜55% で、
それを明確に超えないパターンは情報を持っていない。
